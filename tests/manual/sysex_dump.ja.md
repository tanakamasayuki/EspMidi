# manual/sysex_dump

**実機の音色ダンプ**を実際に転送します。

自動テストのダンプは数バイトです。**実機のダンプは数 KB から数十 KB**あり、キューの分割、出力の排他、送信中の割り込み、相手のタイムアウトがそこで初めて効いてきます。

## 用意するもの

- `examples/UsbHostToUart` または `examples/UartMidiMonitor` を書き込んだボード
- SysEx でダンプを送受信できる機器(シンセサイザー、音源モジュール)
- PC の SysEx ツール(MIDI-OX、SysEx Librarian など)

## 手順と合格条件

### 1. 機器 → PC(受信して中継)

- 機器から音色ダンプを送る(機器側の「Bulk Dump」など)
- **PC 側で受け取ったダンプが、機器が送ったものと完全に一致する**
  - バイト数と、可能ならチェックサムを確認する
- コンソールに出る `SysEx ... bytes` の合計が一致する

### 2. PC → 機器(送って書き戻す)

- PC からダンプを送り返す
- **機器が受け取り、エラーを出さない**
- 音色を鳴らして**元の音に戻っている**ことを確認する

### 3. ダンプ中の割り込み

- ダンプ送信中に鍵盤を弾く
- **ダンプは壊れない**(規則 3: SysEx 送信中は System Real-Time 以外を通さない)
- 弾いた音は**捨てられる**。`sendFailed` / `blockedBySysEx` が増えることをコンソールで確認する
  - これは仕様です。待たせるには出力ごとの遅延バッファが必要なため、捨てて数える選択をしました([../../docs/ROUTING.ja.md](../../docs/ROUTING.ja.md))

### 4. ダンプ中の切断

- ダンプ送信中に受信側の機器を抜く / 電源を切る
- **相手側が待ち続けない**(規則 2: 切断時は `0xF7` で閉じる)
- 挿し直して**次のダンプが正常に通る**(前のダンプの続きにならない)

### 5. BLE 経由

- BLE ポートを使う構成でダンプを送る
- **`ESPMIDI_BLE_SYSEX_BYTES`(既定 320)を超えるダンプは拒否される**
  - `oversizedStreams()` が増える。切り詰めて送らないのは、中途半端なダンプが「一見正しい」形で機器に書き込まれるのを避けるためです
- 320 バイトを超えるダンプを BLE で通す必要がある場合は、この定数を上げます(`EspBle` 側の上限も同時に確認が必要)

## 記録

機器名、ダンプのバイト数、経路(UART / USB / BLE)、所要時間を残します。**BLE の上限に当たった場合は、既定値を上げるかどうかの材料**になります。
