# manual/ble_midi_pairing

**実 BLE MIDI 機器と OS からの見え方**を確認します。

`peer/ble_midi` は ESP32 同士・ペアリングなしで往復します。**実機と OS はペアリングを要求し、再接続の挙動も違います。**

## 用意するもの

- Device 役: `examples/UsbMidiDevice` ではなく、BLE Device ポートを使うスケッチ(`tests/peer/ble_midi/peer_device/` をそのまま使ってよい)
- Host 役: `examples/BleMidiToUart` を書き込んだ ESP32-S3
- 実 BLE MIDI 機器(BLE MIDI キーボード、CME WIDI 系のアダプタなど)
- iOS / Android / macOS / Windows のいずれか

## 手順と合格条件

### 1. Device 役を OS から見る

- ボードを起動する。**OS の BLE MIDI 一覧に現れる**
  - iOS / macOS は「Bluetooth MIDI 設定」から、Windows 10 以降は設定から
- 接続する。**接続でき、DAW にポートとして並ぶ**
- 弾く / 送る。**双方向に届く**
- **アドバタイズ名**が意図した名前で出ることを確認する
- OS 側で切断 → 再接続。**そのまま使える**
- ボードを再起動する。**OS 側の登録が残っていて再接続できる**

### 2. Host 役で実機につなぐ

- BLE MIDI キーボードの電源を入れる。**コンソールに席が現れる**
- 弾く。**MIDI DIN の音源が鳴る**
- キーボードの電源を切る。**`disconnected` が出る**
- もう一度入れる。**同じ席に戻り、ルートを張り直さずに鳴る**
  - 戻らない場合は BLE アドレスが変わっている(ランダムアドレス)。その機器はボンディングが必要
- キーボードを圏外へ持っていって戻す。**再接続して鳴る**

### 3. ペアリングが必要な機器

- ペアリングを要求する機器の場合、スケッチ側でセキュリティ設定が必要です。**BLE のペアリングは `EspMidi` の担当外**なので `EspBle` 側の設定で行います
- ボンディング後に**両側を再起動**する。**再接続できる**

### 4. レイテンシ

- 鍵盤を弾いて**遅れが実用的か**を聴感で確認する
- BLE MIDI はタイムスタンプを持ちますが、**このライブラリは解釈しません**。並べ替えもしないので、体感は BLE リンクと相手の実装で決まります

### 5. 共存

- BLE HID や独自 GATT サービスを同時に持つスケッチで**両方動く**ことを確認する

## 記録

機器名、OS とバージョン、ペアリングの要否、アドレスが固定かランダムかを残します。**ランダムアドレスの機器は席が毎回変わる**ので、それが実運用で問題になるかはここでしか分かりません。
