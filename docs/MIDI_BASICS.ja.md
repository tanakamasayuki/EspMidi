# MIDI の注意事項とインターフェース別の注意点

**MIDI で困ることの大半は、このライブラリではなく MIDI 自体の仕様です。** ここに集めてあります。使い方は [GUIDE.ja.md](GUIDE.ja.md) です。

## MIDI 自体

### 音は流れていません

MIDI が運ぶのは「**ド の鍵盤が強さ 100 で押された**」という指示だけです。音は受け取った側が作ります。だから

- MIDI ケーブルを音源につないでも、**音源が対応する音色になっていなければ意図した音は出ません**
- 遅れは「音が遅れる」のではなく「指示が遅れて音源が鳴り始める」です
- 録音しても波形ではなく操作の記録です

### ステータスバイトとデータバイト

バイトの最上位ビットで役割が決まります。

| 値 | 種類 |
| --- | --- |
| `0x80`〜`0xFF` | **ステータスバイト**(メッセージの始まり) |
| `0x00`〜`0x7F` | **データバイト**(値。7 bit = 0〜127) |

だから **MIDI の値はほぼすべて 0〜127** です。128 以上は表現できません。`espmidi::Message` は書き込み時に必ずマスクするので、計算がはみ出しても線に不正なバイトは出ません。

### チャンネルは 0 始まり、機器の表示は 1 始まり

**定番の間違いです。**

```cpp
transform.channel = 1;   // 機器の表示では「ch2」
message.channel() + 1    // 表示用にはこう
```

このライブラリは一貫して 0 始まり(`0`〜`15`)です。機器のパネルや DAW は `1`〜`16` と表示します。

GM では **ch10(0 始まりでは 9)がドラム**です。ここへメロディを送ると打楽器が鳴ります。

### ノート番号 60 は「中央のド」だが名前は機器によって違う

番号は共通ですが、**その番号を C3 と呼ぶか C4 と呼ぶかは機器によって違います**。1 オクターブずれて見えても番号は合っている、ということがよくあります。番号で話すのが安全です。

### velocity 0 のノートオンはノートオフ

**これを知らないと「音が鳴り止まない」バグになります。**

```
0x90 60 100  → ノートオン
0x90 60 0    → ノートオフ(!)
0x80 60 0    → ノートオフ
```

古い機器は後者を使わず、すべて velocity 0 のノートオンで消音します。自分で判定するときは両方を見てください。

- `espmidi::messageKind()` は velocity 0 のノートオンを `KindNoteOff` と分類します
- `espmidi::Transform` は velocity 0 を変換しません(スケールすると止まらなくなるため)
- `espmidi::ControlOutput` は 0 として扱うので、LED が点いたままになりません

### ノートオフは必ず来るとは限らない

ケーブルを抜く、機器が固まる、送信側がクラッシュする。**鳴りっぱなしになります**。受け側で「All Notes Off」(`0xB0 123 0`)を送れるようにしておくと救えます。このライブラリは自動では送りません(MIDI を解釈しないため)。

### running status: ステータスバイトが省略される

同じ種類が続くとき、送信側はステータスバイトを省略できます。

```
0x90 60 100   ノートオン
     62 100   ← 同じ 0x90 の続き
```

**受け取ったバイトを素朴に読むと壊れます。** このライブラリのパーサが解決するので、`espmidi::Message` には必ずステータスが入っています。送信側では使いません([DEVELOPMENT_PLAN.ja.md](DEVELOPMENT_PLAN.ja.md) の Phase 5)。

### System Real-Time はどこにでも割り込む

`0xF8`〜`0xFF` は**他のメッセージの途中、SysEx の途中にも**入ります。

| | |
| --- | --- |
| `0xF8` Clock | 1 拍あたり **24 通**。テンポ 120 で毎秒 48 通 |
| `0xFA` / `0xFB` / `0xFC` | Start / Continue / Stop |
| `0xFE` Active Sensing | 約 300 ms ごと。「まだ生きている」 |
| `0xFF` System Reset | |

**Clock と Active Sensing はログを埋めます。** モニタするときはフィルタで落としてください。

```cpp
espmidi::Filter quiet;
quiet.kinds = static_cast<uint16_t>(espmidi::KindAll & ~espmidi::KindSystemRealTime);
```

### SysEx は長く、機器ごとに違い、途中で終わることがある

System Exclusive(`0xF0` … `0xF7`)は機器固有のデータです。音色ダンプは数 KB から数十 KB になります。

- **中身は機器のメーカーが決めます。** このライブラリは解釈せず運びます
- **チャンク(断片)で届きます。** `chunkStart` / `chunkEnd` で 1 本のストリームを表します
- **打ち切られることがあります。** `0xF7` 以外のステータスバイトでも終わります
- 経路は**開始時に確定**します。途中で切り替わりません(規則 1、[ROUTING.ja.md](ROUTING.ja.md))
- 送信中の通常メッセージは**捨てられます**(規則 3)

### Program Change だけでは音色が変わらないことがある

音色を選ぶには Bank Select(CC 0 = MSB、CC 32 = LSB)を送ってから Program Change を送ります。順番が逆だと前のバンクのままです。

### Pitch Bend は 14 bit

2 つのデータバイトで LSB → MSB の順、中央が 8192(`0x00 0x40`)です。7 bit ではありません。

### 帯域は思ったより狭い

31250 baud、8N1 なので **1 バイト約 0.32 ms、3 バイトのメッセージで約 1 ms**です。

- 10 音の和音を同時に押すと、最後の音は **約 10 ms 遅れます**(仕様どおり)
- Clock を流しながら大量の CC を送ると詰まります
- USB MIDI と BLE MIDI にはこの制限はありません(はるかに速い)

つまみを回したときに CC を出しすぎないことが実用上重要です。`espmidi::Analog` のヒステリシスと「値が変わったときだけ送る」がこのためにあります。

### MIDI Thru とループ

「入ってきたものをそのまま出す」を作ると、相手も同じことをしていた場合に**無限ループ**になります。このライブラリは**既定で来た元のエンドポイントへ返しません**が、**2 つのポートが同じ物理リンクの両端**の場合は検出できません(別エンドポイントなので)。その 2 つを直結しないでください。

## インターフェース別

### UART / MIDI DIN

**電気的に危険な唯一のインターフェースです。**

- MIDI は **5V のカレントループ**です。電圧ではなく電流で信号を送ります
- **MIDI IN は絶縁が必須**です。フォトカプラ(6N138 など)を使います
- **MIDI DIN ソケットを ESP32 の GPIO に直結してはいけません。** 3.3V の GPIO が壊れます
- MIDI OUT は 220Ω × 2 で作ります
- GND を相手と直結しないのが絶縁の目的です。**シェル(pin 2)を両側で繋がない**

配線が正しければ、ソフト側は `loopback/uart_midi`(配線ゼロで通るテスト)で切り分けられます。**そちらが通ってこちらが通らないなら、原因はハードウェアです。**

手順は [`../tests/manual/uart_midi_din.ja.md`](../tests/manual/uart_midi_din.ja.md) にあります。

### USB Device(PC から見える側)

- **1 つの USB MIDI インターフェースに「cable」が最大 16 本**あり、PC からは cable ごとに別ポートとして見えます
- **cable 数はホスト視点の名前**です。`inCableCount` は device → host なので、このライブラリでは**出力**ポートです([PORTS.ja.md](PORTS.ja.md))
- **PC が構成する前は送信できません。** 起動直後の送信は失敗し `sendFailed` が増えます
- **cable を増やすと descriptor が大きくなります。** 1 cable で 92 バイト、16 cable で 572 バイト。HID や CDC と同居する複合構成では上限に当たります
- **cable ごとの名前は付けられません。** ポート名は OS 側の命名になります
- ESP-IDF の USB Host は列挙時に **256 バイトを超える configuration descriptor を拒否**します。PC 相手なら 16 cable でも動きますが、ESP32 同士では通りません

### USB Host(機器を挿す側)

- **列挙には時間がかかります。** 挿してすぐには席ができません
- **MIDI インターフェースの claim が列挙より遅れることがあります。** ポートは諦めずに再確認します(polling)
- **シリアル番号を持たない機器は、再接続で新しい席になります。** 前の機器のルーティングを別の機器に渡さないためです。`ESPMIDI_MAX_USB_HOST_DEVICES` を使い切ると新しい機器が入りません(`refusedDevices()`)
- **1 機器 = 1 エンドポイント**です。同一方向に複数の bulk endpoint を持つ機器は表現できません
- **cable 数 0 は「その方向が無い」**です。送信専用の機器には入力ポートしかできません
- **バスパワーの機器はセルフパワーのハブを使ってください。** ESP32 の 5V 供給には限りがあります

### BLE MIDI

- **タイムスタンプを持つ唯一のインターフェース**です。13 bit ミリ秒(0〜8191)で、約 8 秒で折り返します。このライブラリは**運ぶだけで解釈しません**
- **レイテンシとジッタが最大です。** 接続間隔(最短 7.5 ms)に縛られるので、演奏用途では UART や USB より不利です
- **ダンプは既定 320 バイトまで**です(`ESPMIDI_BLE_SYSEX_BYTES`、`EspBle` 側の上限と同じ)。超えると**切り詰めずに拒否**します。中途半端なダンプが「一見正しい」形で機器に書き込まれるのを避けるためです
- **席ができるのはサービスの発見と購読が終わったとき**で、リンクが繋がった時点ではありません
- **ランダムアドレスの機器は毎回新しい席になります。** 席の照合に BLE アドレスを使うためです。固定させるにはボンディングが必要です
- **ペアリングは `EspMidi` の担当外**です。`EspBle` 側で設定します
- iOS / macOS は「Bluetooth MIDI 設定」から接続します。**DAW のポート一覧に自動では出ません**

## このライブラリがやらないこと

MIDI の仕様のうち、**意図的に扱わないもの**です。

| | 理由 |
| --- | --- |
| SysEx の中身の解釈 | 機器固有。運ぶだけにすると、知らない機器でも通る |
| 時間の解釈・並べ替え・遅延 | タイムスタンプは運ぶが解釈しない。順序を変えないので何が起きたか追える |
| All Notes Off の自動送信 | MIDI を解釈しない方針の裏返し。必要ならスケッチが送る |
| 音源・シーケンサ・DAW 機能 | 範囲外([REQUIREMENTS.ja.md](REQUIREMENTS.ja.md)) |
| MIDI 2.0 / UMP | 未対応。ただし内部表現を UMP に地続きにしてある([DECISIONS.ja.md](DECISIONS.ja.md) の決定 1) |
