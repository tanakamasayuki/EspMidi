# MIDI DIN のハードウェア

[English](HARDWARE.md)

**MIDI DIN の物理層はこのライブラリの外側です。** それでも ESP32 につなぐ人が必ず通る場所なので、規格が要求していることをここにまとめます。

**正典は次の 2 つです。設計するときは必ず原典を確認してください。**

| | |
| --- | --- |
| [MIDI 1.0 Detailed Specification (M1 v4.2.1)](https://midi.org/midi-1-0-detailed-specification) | 本体。日本語版は [AMEI](https://amei.or.jp/midistandardcommittee/MIDIspcj.html) が無料公開している Ver 4.2 |
| [**CA-033 MIDI 1.0 Electrical Specification Update (2014)**](https://www.midi.org/wp-content/uploads/wpforo/default_attachments/1709416667-ca33-MIDI-10-Electrical-Specification-Update.pdf) | **Hardware 章の差し替え**。3.3V 信号と RF グラウンドを追加 |

> **AMEI の日本語 PDF(Ver 4.2)の回路図は 5V 前提です。** 3.3V の値は 2014 年の CA-033 で追加されたもので、日本語版には入っていません。**ESP32 は 3.3V なので、こちらを見てください。** CA-033 は MMA と AMEI の連名承認です。

以下は CA-033 の要点を実装者向けにまとめたものです。数値は同文書によります。

## 電気的な基本

| | |
| --- | --- |
| ボーレート | **31.25 kbaud ±1%**、非同期 |
| フレーム | スタート 1 + データ 8 + ストップ 1 = **10 bit / 320 µs** |
| ビット順 | **LSB first** |
| 論理 | **論理 0 = 電流 ON** |
| ループ電流 | **5 mA** |
| 立ち上がり / 立ち下がり | **2 µs 未満** |

**1 つの出力が駆動してよい入力は 1 つだけ**です。分配したいときは Thru を使います。

## MIDI OUT

送信側は**電流を流す側**です。絶縁は受信側が持つので、送信側にフォトカプラは要りません。

- ピン 4 と ピン 5 にそれぞれ直列抵抗を入れます(短絡電流制限を兼ねます)
- **ピン 2(シールド)を GND に落とすのは送信側だけ**です
- UART は 8-N-1

### 抵抗値

| | +5V ±10% | **+3.3V ±5%** |
| --- | --- | --- |
| R_A(ピン 4 → +V) | 220Ω 5% **0.25W** | **33Ω 5% 0.5W** |
| R_C(ピン 5 → バッファ出力) | 220Ω 5% **0.25W** | **10Ω 5% 0.25W** |

**3.3V では R_A が 0.5W である必要があります。** 3.3V 電源に直結されているので、MIDI ケーブルが短絡したときの消費が最大 0.383W になるためです。CA-033 は「0.125W の 130Ω を 4 本並列で 32.5Ω / 0.5W」という代替も挙げています。

**3.3V ではバッファがオープンコレクタ / オープンドレインである前提**です。だから R_C 側は 0.25W で足ります。**プッシュプルの汎用バッファを使う場合は、短絡時の電流がバッファの定格を超えないか確認してください。**

### 3.3V の相性

CA-033 は「**仕様に厳密に従う受信側とは互換**」としています。互換でない可能性があるのは次の 2 つです。

- **絶縁していない受信側。** 電圧感度があるので、下がった信号電圧で閾値を超えない可能性があります
- **ピン 4 から電源を取る機器。** 3.3V では動作に足りない場合があります

どちらも本来の仕様から外れた設計です。**古い機材につなぐときは 5V 側の値で作るほうが安全**という判断はありえます。

## MIDI IN

**受信側は必ず絶縁します。** ここが MIDI の要です。

| | |
| --- | --- |
| フォトカプラ | **Sharp PC-900V** または **HP 6N138**(CA-033 が挙げている例)。**5 mA 未満でオンになること**、立ち上がり / 立ち下がりが 2 µs 未満であること |
| R_B | **220Ω**(フォトカプラの LED と直列) |
| D1 | **1N914**(LED の逆電圧保護) |
| R_D | フォトカプラと V_RX による。**PC900V / V_RX = 5V で 280Ω が推奨値** |

- **ピン 2 を受信側 GND へ直流で落としてはいけません。** グラウンドループを作らないためです
- ピン 1 と 3 は未使用。受信側でも送信側でも未接続にします
- ジャックのシールド端子も**直流で GND に落としません**

### ESP32 につなぐとき

フォトカプラの出力は V_RX でプルアップされた**オープンコレクタ**なので、**V_RX を 3.3V にすれば ESP32 の GPIO へ直接入れられます。** R_D はそのフォトカプラと 3.3V に合わせて選び直してください(上の 280Ω は PC900V + 5V の値です)。

> **MIDI DIN ソケットを GPIO へ直結してはいけません。** 相手が流す 5 mA と、そちらの電源基準の電圧が、そのまま 3.3V の GPIO に来ます。

## Thru

MIDI IN で受けた信号をそのまま出す回路です。R_E と R_F は **MIDI OUT の R_A / R_C と同じ選び方**をします(5V なら 220Ω 対、3.3V なら 33Ω / 10Ω)。

**数珠つなぎには限界があります。** フォトカプラの応答時間で立ち上がり / 立ち下がりが鈍り、その誤差が段ごとに**同じ方向に積み上がる**からです。CA-033 は **3 台を超える連結では高速なフォトカプラを使うべき**としています。

## コネクタとケーブル

| | |
| --- | --- |
| コネクタ | **DIN 5 ピン(180°)** メス パネル取付。例: Switchcraft 57PC5F |
| ケーブル | **最大 15 m(50 ft)**、シールド付きツイストペア |
| プラグ | DIN 5 ピン オス。例: Switchcraft 05GM5M |
| シールド | **両端でピン 2 のみに接続** |

**ケーブルのシールドをプラグのシェル(バレル)に接続してはいけません。**

## EMI / EMC のオプション(CA-033 で追加)

規格上は必須ではありません。**MIDI の動作には不要**で、EMC 規制対応が要るときだけ使います。

| | |
| --- | --- |
| フェライトビーズ | **100 MHz で 1 kΩ**(例: MMZ1608Y102BT)。信号ピンに入れる。**ジャックのできるだけ近くに置く** |
| MIDI IN のピン 2 | **0.1 µF 程度のコンデンサ**経由で GND へ。直流は切ったまま RF だけ落とせる |
| MIDI IN のジャックシールド | 同じく 0.1 µF 経由。**直結は今も禁止** |
| MIDI OUT / Thru のジャックシールド | 未接続、または **GND へ直結してよい** |

コンデンサを入れる理由は、ケーブルのインダクタンスで高周波ではシールドが効かなくなるからです。0.1 µF なら 10 MHz で約 0.16Ω(ほぼ短絡)、60 Hz で約 26.5 kΩ(切れている)になります。

## ソフトとハードの切り分け

**配線を疑う前に、ソフトを除外できます。**

```sh
cd tests
uv run --env-file .env pytest loopback/uart_midi/
```

このテストは**配線ゼロ**で通ります(GPIO マトリクスで UART1_TX と UART2_RX を同じピンに載せます)。

- **通る → ソフトは正しい。** 原因は回路か配線か相手の機器です
- **通らない** → まずそちらを直します

実機の確認手順は [`../tests/manual/uart_midi_din.ja.md`](../tests/manual/uart_midi_din.ja.md) にあります。
