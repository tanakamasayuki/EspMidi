# UsbHostToUart

[English](README.md)

USB MIDI キーボードで MIDI DIN の音源を鳴らしながら、**同じ演奏を PC にも流します**。PC で録りながら音源を弾けます。

[../../docs/USE_CASES.ja.md](../../docs/USE_CASES.ja.md) の UC1 です。互いを知らない 3 つのトランスポートをルートだけで繋ぐ、このライブラリの要点がそのまま出ています。

## 構成

```text
USB MIDI キーボード ──→ ┐
                        ├──→ MIDI DIN OUT(音源)
                        └──→ PC(USB Device ポート 1)
PC(ポート 1)────────────→ MIDI DIN OUT にも
```

USB Host と USB Device を同時に使うので **USB ペリフェラルが 2 つ必要**です。対象は ESP32-P4 です。

| 定数 | 既定 | 意味 |
| --- | --- | --- |
| `RX_PIN` | 20 | MIDI IN |
| `TX_PIN` | 19 | MIDI OUT(音源へ) |

## 読みどころ

**キーボードをどこにも書いていません。** 席は挿したときに現れるので、ルートは `espmidi::InGroup::all()` に対して張ります。抜き差ししてもルートは消えず、挿し直せばそのまま続きます。

**ルートは来た元のエンドポイントへは返しません。** だから「全入力を音源と PC へ」と書いても、PC が自分にエコーしたり DIN 入力が自分の出力へ回ったりしません。

**席の出入りは通知で分かります。** `registry.addListener()` が拾うのは「席が現れた」と「席の状態が変わった」の 2 つだけです。席は削除されないので、それで足りています。

**cable 数の向きは Host と Device で逆です。** `EspUsbHost` の数は既にホスト視点なので USB Host ポートでは反転せず、USB Device ポートでは反転します。詳しくは [../../docs/PORTS.ja.md](../../docs/PORTS.ja.md)。

## 準備と実行

1. [サンプル入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [UsbHostToUart.ino](UsbHostToUart.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<EspMidiEspUsbDevice.h>`, `<EspMidiEspUsbHost.h>`, `<EspMidiUart.h>`

3. 書き込んだらシリアルモニタを115200 baudへ合わせます。起動ログとソースの操作条件を確認します。

## 動作の流れ

USB HostのMIDIをUARTへルートする例です。詳細なAPIとデータの扱いは次の項目で確認します。

以下はソース内で最初に現れるAPIの順です。コールバック登録の位置は、実際の呼び出し順序とは異なります。

1. `usbHost.begin(...)` — 前提となる機器を準備してから初期化し、結果を返すAPIでは成否を確認します。
2. `router.addRoute(...)` — 切断と意図しないループを考慮して、入力と出力のEndpoint／グループを登録します。
3. `keyboards.update(...)` — 例にある実行場所から定期的に呼び、対象の処理を進めます。

変更する前に確認する定数: `RX_PIN`, `TX_PIN`。GPIOやチャンネル、容量などは用途に合わせます。

## APIの使い方と注意点

各Transportとポートを初期化し、ルートを登録してから、例にあるRouter／ポート／スタックの処理を継続します。MIDIを転送するだけでは音は鳴らず、楽器やソフト音源へ接続します。USB／BLEの接続でポートの可用性は変わるため、グループや安定した識別子と、現在のEndpointは別の役割です。

双方向ルートを追加する際は意図しないループを防ぎ、注入したNote OnにNote Offを対応させます。UART MIDIにはDIN用の適切な電気回路が必要で、Socketへ直接GPIOをつなぐ配線ではありません。Filter追加時もPacket長とSysEx viewの寿命を保ちます。

コールバック引数への参照は永続領域ではありません。

## 確認と問題の切り分け

USB HostのMIDIをUARTへルートすることを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../README.ja.md)へ進んでください。
