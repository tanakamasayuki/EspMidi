# SimpleMidiOut

[English](README.md)

**最小のスケッチです。** 1 ポート・送信のみ。ドレミファソラシドを繰り返し鳴らします。

音源を MIDI OUT につないで電源を入れれば音が出ます。最初に動かすならこれです。

## 配線

`TX_PIN`(既定 GPIO19)→ MIDI OUT 回路(220Ω × 2)→ 音源の MIDI IN。

**MIDI IN 側は使いません。** 送信だけなので `begin()` の `rxPin` に `-1` を渡しています。

## 読みどころ

**`router.update()` を呼ぶまで線に出ません。**

```cpp
sketch.sendShort(0x90, 60, 100);  // 積むだけ
router.update();                  // ここで出る
```

**`espmidi::AppPort` は「スケッチというポート」です。** ほかのポートと同じようにルーティングされるので、「PC にも同時に送りたい」と言われても**ルートを 1 本足すだけ**です。

**ノートオフを忘れると鳴り続けます。** MIDI 自体の注意点は [../../docs/MIDI_BASICS.ja.md](../../docs/MIDI_BASICS.ja.md) にまとめてあります。

次は [`../SimpleMidiIn/`](../SimpleMidiIn/)、そのあと [`../SameCodeAnyPort/`](../SameCodeAnyPort/) です。ガイドは [../../docs/GUIDE.ja.md](../../docs/GUIDE.ja.md)。

3. 書き込み後は画面／入力など、この例の出力先で確認します。シリアルを使う場合はソースの初期化条件に合わせます。

## 動作の流れ

MIDIメッセージを出力ポートへ送る例です。詳細なAPIとデータの扱いは次の項目で確認します。

以下はソース内で最初に現れるAPIの順です。コールバック登録の位置は、実際の呼び出し順序とは異なります。

1. `din.begin(...)` — 前提となる機器を準備してから初期化し、結果を返すAPIでは成否を確認します。
2. `router.addRoute(...)` — 切断と意図しないループを考慮して、入力と出力のEndpoint／グループを登録します。
3. `router.update(...)` — 例にある実行場所から定期的に呼び、対象の処理を進めます。

変更する前に確認する定数: `TX_PIN`。GPIOやチャンネル、容量などは用途に合わせます。

## APIの使い方と注意点

各Transportとポートを初期化し、ルートを登録してから、例にあるRouter／ポート／スタックの処理を継続します。MIDIを転送するだけでは音は鳴らず、楽器やソフト音源へ接続します。USB／BLEの接続でポートの可用性は変わるため、グループや安定した識別子と、現在のEndpointは別の役割です。

双方向ルートを追加する際は意図しないループを防ぎ、注入したNote OnにNote Offを対応させます。UART MIDIにはDIN用の適切な電気回路が必要で、Socketへ直接GPIOをつなぐ配線ではありません。Filter追加時もPacket長とSysEx viewの寿命を保ちます。

コールバック引数への参照は永続領域ではありません。

## 確認と問題の切り分け

MIDIメッセージを出力ポートへ送ることを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../README.ja.md)へ進んでください。
