# GpioControls

[English](README.md)

**つまみ 2 個・ボタン 2 個・エンコーダ 1 個の MIDI コントローラです。** 出力は USB MIDI と MIDI DIN の**両方に同時**に出ます。

[../../docs/USE_CASES.ja.md](../../docs/USE_CASES.ja.md) の UC10 です。ここではボードは MIDI ルータではなく **MIDI 機器**です。

## 構成

```text
つまみ・ボタン・エンコーダ ──→ [アプリケーションポート] ──→ USB MIDI
                                                      └─→ MIDI DIN OUT
USB MIDI ──→ LED(ノート 60)と調光(CC 20)
```

| コントロール | 送るもの |
| --- | --- |
| つまみ 1 / 2 | CC 7(Volume)/ CC 11(Expression) |
| ボタン 1 | ノート 60 |
| ボタン 2 | CC 64(Sustain)、**ラッチ**(モーメンタリスイッチをトグルとして使う) |
| エンコーダ | CC 16、相対(2 の補数) |

## 読みどころ

**ヘルパーはピンに触りません。** スケッチが読んだ値を渡すだけです。だから同じヘルパーが ADC でもポートエキスパンダでもタッチセンサでもネットワーク越しの値でも動きます。**時刻も引数**なので、デバウンスやテンポがテストできます([../../src/EspMidiControl.h](../../src/EspMidiControl.h))。

```cpp
knobs[i].update(analogRead(KNOB_PINS[i]));            // 値を渡すだけ
buttons[i].update(digitalRead(BUTTON_PINS[i]) == LOW, millis());
```

**つまみは動いたときだけ送ります。** ADC は 4096 段、CC は 128 段なので、ほとんどの動きは同じ値に着地します。加えて `hysteresis`(既定 8 カウント)があるので、**誰も触っていないつまみがリンクを CC で埋めることがありません**。

**LED 側は鏡像です。** どのメッセージに反応するかは `espmidi::Filter` で書きます — ルートに置くフィルタと同じものです。ノートオンでベロシティ 0 は消灯になるので、**LED が点いたままになりません**。

**エンコーダの相対形式は 3 種類選べます。** 標準が無く、間違えるとパラメータが逆に回るか動きません。

**アプリケーションポートに乗っているので、出力先は増やせます。** ルートを 1 本足せば BLE にも同時に出ます。

## 準備と実行

1. [サンプル入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [GpioControls.ino](GpioControls.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<EspMidiEspUsbDevice.h>`, `<EspMidiUart.h>`

3. 書き込んだらシリアルモニタを115200 baudへ合わせます。起動ログとソースの操作条件を確認します。

## 動作の流れ

GPIO入力からMIDIのControlイベントを送る例です。詳細なAPIとデータの扱いは次の項目で確認します。

以下はソース内で最初に現れるAPIの順です。コールバック登録の位置は、実際の呼び出し順序とは異なります。

1. `usb.begin(...)` — 前提となる機器を準備してから初期化し、結果を返すAPIでは成否を確認します。
2. `router.addRoute(...)` — 切断と意図しないループを考慮して、入力と出力のEndpoint／グループを登録します。
3. `led.handle(...)` — 実行中のタスクのハンドルを取得します。終了後まで保持して使わないようにします。
4. `encoder.update(...)` — 例にある実行場所から定期的に呼び、対象の処理を進めます。

変更する前に確認する定数: `DIN_RX_PIN`, `DIN_TX_PIN`, `ENCODER_A_PIN`, `ENCODER_B_PIN`, `LED_PIN`。GPIOやチャンネル、容量などは用途に合わせます。

## APIの使い方と注意点

各Transportとポートを初期化し、ルートを登録してから、例にあるRouter／ポート／スタックの処理を継続します。MIDIを転送するだけでは音は鳴らず、楽器やソフト音源へ接続します。USB／BLEの接続でポートの可用性は変わるため、グループや安定した識別子と、現在のEndpointは別の役割です。

双方向ルートを追加する際は意図しないループを防ぎ、注入したNote OnにNote Offを対応させます。UART MIDIにはDIN用の適切な電気回路が必要で、Socketへ直接GPIOをつなぐ配線ではありません。Filter追加時もPacket長とSysEx viewの寿命を保ちます。

コールバック引数への参照は永続領域ではありません。

## 確認と問題の切り分け

GPIO入力からMIDIのControlイベントを送ることを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../README.ja.md)へ進んでください。
