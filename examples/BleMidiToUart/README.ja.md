# BleMidiToUart

[English](README.md)

**ワイヤレスの BLE MIDI キーボードで、MIDI DIN の音源を鳴らします。** PC は要りません。

[../../docs/USE_CASES.ja.md](../../docs/USE_CASES.ja.md) の UC5 です。逆向きにも流れるので、MIDI DIN 入力に来たものはキーボードへ送られます(ランプや画面を持つコントローラを光らせられます)。

## 構成

```text
BLE MIDI キーボード ──→ MIDI DIN OUT(音源)
MIDI DIN IN ────────→ BLE MIDI キーボード
```

| 定数 | 既定 | 意味 |
| --- | --- | --- |
| `RX_PIN` | 20 | MIDI IN |
| `TX_PIN` | 19 | MIDI OUT(音源へ) |

## 読みどころ

**スキャンと接続はスケッチの仕事、接続の中身はポートの仕事です。** だから `discover()` はどこにも書いていません。BLE は `EspMidi` の担当外です([../../docs/CORE_DESIGN.ja.md](../../docs/CORE_DESIGN.ja.md))。

**キーボードをどこにも書いていません。** ルートは 2 本ともポート群に対して張るので、抜き差ししても張り直しません。

```cpp
router.addRoute(espmidi::InGroup::all(), din.out());   // 鳴らすものは音源へ
router.addRoute(din.in(), espmidi::OutGroup::all());   // DIN 入力は繋がっているものへ
```

**ルートは来た元のエンドポイントへは返しません。** だから 2 本目は音源の出力へ回らず、キーボードにだけ届きます。

**再接続すると同じ席に戻ります。** BLE アドレスが識別子なので、圏外に出て戻ってきてもルートは生きたままです。

**タイムスタンプが付いてくる唯一のポートです。** 13 bit ミリ秒(`TimestampUnit::Milliseconds13`)で、このライブラリは中身を解釈しません。

## 準備と実行

1. [サンプル入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [BleMidiToUart.ino](BleMidiToUart.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<EspMidiEspBle.h>`, `<EspMidiUart.h>`

3. 書き込んだらシリアルモニタを115200 baudへ合わせます。起動ログとソースの操作条件を確認します。

## 動作の流れ

BLE MIDIとUART MIDIを双方向にルートする例です。詳細なAPIとデータの扱いは次の項目で確認します。

以下はソース内で最初に現れるAPIの順です。コールバック登録の位置は、実際の呼び出し順序とは異なります。

1. `ble.begin(...)` — 前提となる機器を準備してから初期化し、結果を返すAPIでは成否を確認します。
2. `ble.scanner().start(...)` — 設定した入口から処理を開始します。実行中はコンテキストとオブジェクトの寿命を保ちます。
3. `router.addRoute(...)` — 切断と意図しないループを考慮して、入力と出力のEndpoint／グループを登録します。
4. `ble.update(...)` — 例にある実行場所から定期的に呼び、対象の処理を進めます。

変更する前に確認する定数: `RX_PIN`, `TX_PIN`。GPIOやチャンネル、容量などは用途に合わせます。

## APIの使い方と注意点

各Transportとポートを初期化し、ルートを登録してから、例にあるRouter／ポート／スタックの処理を継続します。MIDIを転送するだけでは音は鳴らず、楽器やソフト音源へ接続します。USB／BLEの接続でポートの可用性は変わるため、グループや安定した識別子と、現在のEndpointは別の役割です。

双方向ルートを追加する際は意図しないループを防ぎ、注入したNote OnにNote Offを対応させます。UART MIDIにはDIN用の適切な電気回路が必要で、Socketへ直接GPIOをつなぐ配線ではありません。Filter追加時もPacket長とSysEx viewの寿命を保ちます。

コールバック引数への参照は永続領域ではありません。

## 確認と問題の切り分け

BLE MIDIとUART MIDIを双方向にルートすることを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../README.ja.md)へ進んでください。
